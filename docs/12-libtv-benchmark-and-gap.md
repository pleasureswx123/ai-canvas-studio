# LibTV Benchmark And Product Gap

本文用于回答一个关键问题：新项目重构后，是否真的比旧版更好，是否有机会靠近专业 AI 视频创作工具。

结论先行：当前 `my-canvas-next` 是工程化基线，不是专业级视频创作产品。它解决了旧项目工程结构混乱的问题，但还没有完整解决专业创作者的工作流问题。如果继续只做代码重构和局部 UI 美化，最终很可能出现“架构变好了，产品反而不如旧版”的风险。

## Boss View

老板不会只看代码结构。老板会看：

- 用户能不能更快完成创作。
- 是否比旧版更顺手。
- 是否有旧版已有能力缺失。
- 是否能展示出专业产品气质。
- 是否能支撑后续商业化、团队开发和稳定迭代。

所以后续判断标准必须从“代码是否更工程化”升级为：

```text
核心创作任务完成效率 + 旧版能力保真度 + 专业工具体验 + 架构可持续性
```

## What LibTV Appears To Be

基于公开资料和当前截图，LibTV 的核心定位是：

- 一站式 AI 视频创作平台。
- 无限画布 + 节点式工作流。
- 覆盖剧本、分镜、画面、视频、音频、导出。
- 面向人类创作者，也面向 AI Agent 自动化创作。
- 用项目首页、最近项目、沉浸画布、左侧工具栏、浮层工具箱组织产品。

公开资料提到 LibTV 支持剧本节点、分镜节点、视频节点，支持从创意输入到成片导出，并聚合多模型能力。

## LibTV Interaction Patterns From Screenshots

### 1. Project Home

LibTV 不是一打开就是复杂后台，而是先给用户一个创作入口：

- 顶部品牌栏。
- Banner / 活动 / 模板展示。
- 最近项目卡片。
- “开始创作”作为第一张强入口卡片。
- 项目卡片用大封面图，而不是列表行。

这让用户第一眼知道：

```text
我在哪里，我能开始做什么，我最近做过什么。
```

### 2. All Projects

全部项目页仍然是卡片式，不是管理后台表格：

- 返回入口。
- 新建文件夹。
- 项目封面卡片。
- 项目名称和日期。
- 更多操作藏在菜单中。

重点是创作资产，而不是 CRUD 管理。

### 3. Canvas Workspace

画布页是全屏沉浸式：

- 顶部轻导航，只保留品牌、项目名、保存、分享、通知等关键动作。
- 中间是大画布。
- 左侧是竖向工具栏。
- 底部是缩放和视图控制。
- 节点创建以浮层或快捷卡片出现。
- 空画布中央给“可双击画布自由生成节点”的引导。

这比传统三栏后台更像创作工具。

### 4. Node Launcher

添加节点不是一排普通按钮，而是创作工具箱：

- 文本
- 图片
- 视频
- 视频合成
- 音频
- 脚本
- 上传
- 从图库选择

这说明 LibTV 的思路不是“添加一个表单”，而是“选择一个创作能力”。

### 5. Material Panels

素材不是右侧固定列表，而是可展开浮层：

- 我的工具箱
- 我的素材
- 我的主体库
- 分类 tab
- 预设素材卡片
- 主体库入口

这更接近创作者的资产管理方式。

## Old Version Risk

旧版虽然可能工程化差，但可能有这些优势：

- 功能更全。
- 交互细节更多。
- 某些业务路径已经被用户习惯。
- 高级能力可能在旧版里更接近真实需求。

新项目现在的优势是：

- 架构清晰。
- 数据边界清楚。
- API contract 更稳定。
- 测试和门禁更完整。
- 更容易继续开发。

但如果不继续补产品能力，新项目会被评价为：

```text
更规范，但不好用；更干净，但不如旧版能干活。
```

这是必须避免的。

## Product Direction

后续不应该继续做“泛泛 UI 美化”，而应该围绕专业视频创作工作流补能力。

推荐方向：

1. 项目首页产品化：真实封面、项目分组、模板入口、最近打开。
2. 创作画布产品化：左侧工具箱、节点快捷创建、双击画布创建节点、底部缩放状态。
3. 脚本节点：输入故事梗概，拆分角色、场景、镜头。
4. 分镜节点：从脚本生成分镜卡片，支持单条重生成。
5. 批量生成：分镜图批量生成、分镜视频批量提交和轮询。
6. 角色/主体库：角色三视图、参考图、多角度一致性。
7. 音频节点：旁白、配音、BGM、字幕占位。
8. 导出工作流：把多个视频片段组织成可交付成片。
9. 模板化：把一套节点工作流保存为模板。
10. Agent workflow：让 AI agent 能自动创建脚本、分镜、图片和视频节点。

## Next Milestones

### Phase 8A: Product UX Parity

目标：新项目看起来和用起来都不再像后台。

- [ ] 项目首页：最近项目、全部项目、项目卡片、创建入口。
- [ ] 画布页：顶部轻导航、左侧工具栏、底部缩放栏、浮层工具箱。
- [ ] 素材浮层：我的素材、主体库、生成历史。
- [ ] 空画布引导：双击画布创建节点，提供创作模板入口。
- [ ] 节点视觉重构：减少表单感，提高创作卡片感。

### Phase 8B: Script To Shot

目标：开始接近专业视频创作，而不是只有散点节点。

- [ ] 脚本节点：输入剧情、角色、场景。
- [ ] 分镜节点：把脚本拆成镜头列表。
- [ ] 分镜卡片：每个镜头有画面描述、运动、角色、时长。
- [ ] 批量图片生成：每个分镜生成首帧。
- [ ] 批量视频生成：每个首帧生成视频片段。

### Phase 8C: Character And Asset Consistency

目标：解决 AI 视频最核心的角色/主体一致性。

- [ ] 主体库数据模型。
- [ ] 主体参考图保存。
- [ ] 角色三视图占位能力。
- [ ] 节点引用主体。
- [ ] 生成请求携带主体引用。

### Phase 8D: Export And Delivery

目标：从生成片段走到可交付内容。

- [ ] 时间线或片段列表。
- [ ] 片段排序。
- [ ] 字幕/旁白占位。
- [ ] ffmpeg 合成导出。
- [ ] 导出记录和失败恢复。

## Immediate Recommendation

下一步不要盲目继续堆功能。先做两个动作：

1. 旧版能力审计：逐页逐功能列出旧版已经有的能力、交互和业务路径。
2. LibTV 对标拆解：按首页、项目页、画布、节点、工具箱、素材库、生成链路拆解。

然后按差距决定：

- 哪些必须恢复旧版。
- 哪些要学习 LibTV。
- 哪些是我们自己的差异化。

只有这样，重构才不是“技术工程”，而是“产品升级”。
